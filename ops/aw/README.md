# Подключение AW на mock-данных

Источник — существующий PostgreSQL приложения. AW получает только представление `aw_mock.samples`. Реальные данные пользователей, диалогов и Flue не экспортируются. Новых сервисов, HTTP API, Collector или ClickHouse нет.

Это временный набор для проверки соединения, типов полей, графиков и обновления модели AW. `demo_a` и `demo_b` — условные серии, не бизнес-метрики. Формулы и итоговый контракт аналитики пока не определены.

## Подготовка

Примените миграции API стандартным способом. Для локального API из папки `api`:

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
```

Для полного Docker-развёртывания:

```powershell
docker compose up -d --build --wait api
```

Миграция `0014` создаёт пустую таблицу `public.aw_mock_samples`, схему `aw_mock` и представление `aw_mock.samples`. Моки не загружаются автоматически ни при миграциях, ни при запуске бота.

Все следующие команды выполняются из корня проекта. Ниже используется dev-compose и база `hackathon`. Для полного Compose замените `-f docker-compose-dev.yml` на `-f docker-compose.yml`, а `-d hackathon` на `-d app`. Используйте тот же Compose, что уже запущен; одновременно оба окружения не поднимайте.

## Загрузка и обновление моков

```powershell
Get-Content -Raw ops/aw/seed.sql | docker compose -f docker-compose-dev.yml exec -T postgres psql -X -U postgres -d hackathon
```

Скрипт создаёт 480 точек: две серии по 240 часов, до текущего часа включительно. Повторный запуск обновляет те же идентификаторы и сдвигает временное окно, не создавая дубликатов. Даты хранятся как `timestamptz`; часовой пояс отображения выбирается в AW. Сразу после загрузки скрипт выводит число строк и диапазон дат.

## Пользователь AW

Задайте `AW_READER_PASSWORD` в окружении текущего терминала случайным значением от 32 символов, отдельно от паролей приложения. Не сохраняйте пароль в Git и не используйте администратора PostgreSQL в AW.

```powershell
Get-Content -Raw ops/aw/reader.sql | docker compose -f docker-compose-dev.yml exec -T -e AW_READER_PASSWORD postgres psql -X -U postgres -d hackathon
Remove-Item Env:AW_READER_PASSWORD
```

Скрипт создаёт выделенную роль `aw_mock_reader` или обновляет её пароль. Права выдаются только на чтение представления, без автоматических разрешений на будущие таблицы. Не используйте эту роль для других задач. Если роль уже существует с повышенными привилегиями или членством, скрипт откажется работать. Права, предоставленные всем через `PUBLIC`, действуют и для неё; в окружениях с нестандартными общими разрешениями нужен отдельный аудит доступа.

## Настройка AW

Создайте источник PostgreSQL:

| Настройка | Значение |
|---|---|
| Хост | Адрес PostgreSQL, доступный именно с сервера AW |
| Порт | `POSTGRES_PORT`, по умолчанию `5432` |
| База | `hackathon` для dev или `app` для полного Compose |
| Логин | `aw_mock_reader` |
| Пароль | Заданный `AW_READER_PASSWORD` |
| Представление | `aw_mock.samples` |

Оба Compose публикуют PostgreSQL только на `127.0.0.1`. Удалённый AW не сможет подключиться без настройки защищённого сетевого пути. Используйте поддерживаемый AW SSH-туннель либо VPN/приватную сеть с ограничениями по адресу сервера AW и подходящей настройкой SSL. Не открывайте порт PostgreSQL всему интернету. `localhost` в AW означает сервер AW, а не компьютер разработчика. Для AW в общей Docker-сети адрес — `postgres:5432`.

Если представление не видно в списке объектов, используйте SQL-источник:

```sql
SELECT id, recorded_at, series, value, is_mock
FROM aw_mock.samples
```

В AW создайте модель на основе источника, загрузите данные и настройте расписание загрузки модели в доступном на стенде режиме. Проверочный график: ось времени `recorded_at`, серии `series`, значение `value`. Назовите модель и панель явно `MOCK — проверка подключения`. `is_mock` всегда равен `true`.

Для проверки обновления повторно выполните seed и загрузку модели AW: количество останется 480, временное окно обновится. Обновление открытой страницы панели проверяется отдельно от загрузки модели.

## Удаление моков

```powershell
Get-Content -Raw ops/aw/clear.sql | docker compose -f docker-compose-dev.yml exec -T postgres psql -X -U postgres -d hackathon
```

Удаляются только строки выделенной таблицы `aw_mock_samples`. Представление, права и рабочие таблицы остаются. Затем запустите полную загрузку модели AW, чтобы удалить её старую копию моков; инкрементальное добавление для этого источника не используйте. При необходимости удалите mock-модель и панель средствами AW.

Реальные события Flue пока не подключены. После выбора метрик будет добавлен отдельный реальный источник, без смешивания с `aw_mock.samples`. Очистка моков выполняется явно, не автоматически при появлении реальных данных.
